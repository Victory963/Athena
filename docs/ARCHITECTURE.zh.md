# Athena：住在本机上的自主进化防守 Bot

Athena 是一个个人 AI 防守产品。它住在机主的电脑上，用一句人话当控制面，在封闭的动作清单里选择防守，而不是把电脑交给模型。

本文说明产品论点、怎么用、代码放在哪里、架构怎么分、以及「用 AI 防守被 AI 驱动的网络攻击」时，自主进化到底允许进化什么。本文不提供扫描、利用、载荷、钓鱼文案或攻击步骤。

## 1. 现在它是什么，不是什么

Athena 是可以在本机跑起来的防守 Bot 和一套共享同一宪法的二十二个防守模块。对话在 `/`，控制面在 `/os`。

它不是上市公司，没有已披露的营收、客户、认证或交易所代码。把它写成「可以按公开市场的标准讲清楚的产品」，指的是：边界、适应度、审计和杀开关能够被外人读懂。这不是融资承诺，也不是财务预测。

## 2. 市场论点

网络攻击正在变成模型加工具的循环。攻击代理可以连续试探、改写话术、在获准范围外要新工具，并在人看完一条告警之前换下一手。防守如果只增加告警条数，业务并没有更安全，人只会更累。

这个类别已经有买家。CrowdStrike Charlotte AI、Microsoft Security Copilot、Palo Alto Cortex、SentinelOne Purple AI、Darktrace Cyber AI Analyst、Trend Micro Vision One，以及日本的 LAC 等，都在卖某种「代理参加安全分析或响应」的产品。页上的准确率、客户数和百分比是厂商自述，Athena 没有复测，也不把它们算成自己的业绩。

Athena 占的是另一端：

- 住在机主这台电脑上，而不是先把遥测交到别人的租户。
- 工具清单封死为十五个已签名动作。
- 模型可以提议，不可以自己把清单变长。
- 杀开关不在被评分的那个循环里。
- 适应度惩罚业务损失和物理风险，告警数量不能当作成绩。

攻击越自动化，这种「清单不能自己变长」的防守越有价值。自动攻击最便宜的赢法，是诱使防守代理自己扩大权限。Athena 把这种赢法从架构上拿掉。

## 3. 怎么运行

```bash
npm install
npx prisma migrate dev --name init --skip-seed
npx next dev -p 3030
```

桌面壳：

```bash
npm run bot
```

浏览器打开 http://127.0.0.1:3030 。自检：

```bash
npm run check
```

自检确认二十二个模块、十五个动作的封闭清单，以及进攻说法会被拒绝。数据库是本机 SQLite，连接串在 `.env` 的 `DATABASE_URL`。不要把 `.env`、`prisma/dev.db` 或 `.cache/` 提交出去。

可选：`.env` 里设置了 `ZAI_API_KEY` 时，普通闲聊走智谱 GLM-5.3（Z.AI Chat Completions）。没有密钥时，Bot 仍用封闭规则回答。本仓库仍登记 GLM-5.2 的本机量化包，约 217 GB，下载保持暂停。没有密钥、也没有本机服务时，不要把它说成已经在回答。密钥只留在 `.env`，不要提交。

## 4. 怎么用 Bot

左边是会话列表。

- **新建 Bot**：增加一个会话。名称可以改。乘号删除。会话记在这台浏览器或桌面壳的本地存储里。
- 新会话先问四件事：**查这台电脑**、**共享画面**、**演化防守**、**先聊聊**。没有单独的「次世代升级」按钮。
- **查这台电脑**，或说「查一下我的 pc」：只读进程数、监听端口、内存大约占用、C 盘剩余空间。不读剪贴板、键盘、命令行参数，不扫局域网，不结束进程。
- **共享画面**、**摄像头**：只有点了才开。画面留在本机，用来看偏暗或醒目红色。状态写在预览上，不把「正常 / 稳住了」刷进对话。关掉或系统收回权限就停。
- **演化防守**，或说「演化」：从二十二个模块里走一轮，只执行一个已签名动作，或停在人工闸门。
- **先聊聊**：问候会得到短句。其余闲聊在 GLM 真正接通时才由模型回答；否则仍是短句。进攻请求直接拒绝。
- **对方出招**：在输入框写对方这一手，例如「对方在试探」「登录失败堆高」「委托应用在没有人登录时被使用」「范围扩张」。Athena 只按防守侧形状选定十五个动作之一。范围扩张停在闸门。业务损失已经顶到预算时，对话这一手会记下或退回一格再执行；本机断路器那一路不会偷偷退预算。
- **本机断路**：标题下一行显示失败登录、新计划任务、新启动项、新凭据。窗口可见时大约每 20 秒读一次。触发了就在本机选一个已签名动作，不等云端仪表盘。账户和任务不删除。
- **Hugging Face 回顾**：问公开的 OpenAI 评测代理与 Hugging Face 的对战时，回答公开披露的防守侧事实，不校准分类器，不复述进攻步骤。
- 加号菜单还有附件、防守任务、本机端口授权。附件不上传。任务不会新增工具。

控制面 `/os` 保留模块、架构、审计、路线和 SWOT，给要看账本的人，不是 Bot 的主界面。

## 6. 架构

一条请求从窗口到动作，经过固定的几层。

1. **壳**。Electron 或浏览器只负责显示和采集开关。采集不是后台常开。
2. **意图**。`parseIntent` 先看是不是进攻请求。是就拒绝，后面的模块不会跑。
3. **宪法**。允许的动作只有十五个。禁止项包括付赎金、联系攻击者、对外扫描、给客户发消息、微调基座模型、加工具、加数据源、改目标、关掉杀开关、关掉物理联锁、进入供应商网络、代发监管通知。
4. **决策**。`engine.decide` 根据模块和政策形状选出一个动作，或给出必须问人的理由。
5. **账本**。执行和拒绝写入审计。适应度按公式更新，不按告警条数。
6. **闸门**。范围扩张、新工具、新数据、新目标进入治理提案。人点批准，清单长度仍然是 15。

模型、界面和权重都可以换。宪法这一层不交给正在被评分的模型改。

## 8. 二十二个模块

每个模块只绑定上面的一个动作，或在条件不满足时停在闸门。

证件即焚验证所、字段残值定价所、二次伤害排练场、语言壁垒倒置、个性化钓鱼抗体、通行密钥默认工厂、开户侧影像不信任闸、委托链断路器、勒索可用性壳、披露时钟、市政邮件信任锚、移动目标暴露面、冷链安全调速器、物理包络证、停机权分离器、抗体控制面、自身免疫抑制器、共演化健身房、对手策略分类器、对手成本仪表、治理孪生、学习回路检疫所。

合成租户（北岸出行、南风旅行等）只用于演示。不要把它们写成客户。

## 9. 自主进化的原理

攻击 AI 的优势是循环快：看反馈、换说法、要更多工具。防守 AI 如果复制这个循环，就会自己把权限扩大。Athena 把循环留下，把扩大权限的那一步删掉。

一轮是：

1. **观察**。读已有的防守侧读数：间隔方差、每小时触达、泄漏字段标记命中、重复度、停顿、委托方健康、设定值偏移、每分钟工具调用、范围扩张次数。这些是形状，不是对方主机上的文件。
2. **推断政策类**。节奏过稳、工具突发、范围扩张、话术带泄漏字段标记、序列重复、长停顿后的修正、委托方先变差、设定值漂出包络，或基线。
3. **提议一个动作**。政策类映射到十五个动作之一。模块还可以把不在签署包络里的请求打回闸门。
4. **评估**。用冻结的留出集看分类是否更好。下载量、星标、告警条数都不能晋升。
5. **晋升或问人**。安全且在清单内的控制可以记下。新工具、新数据源、新目标只形成提案。
6. **回滚**。抗体变差、误拦超出预算，就回到上一版，而不是再加一条规则。

适应度：

```text
适应度 = 攻击方成本 − 业务损失 − 4 × 物理风险
```

攻击方成本上升是好事。业务更难做、物理风险上升，会把分数拉下来。所以「多报一条告警」不是进化。

杀开关按下时，节拍直接拒绝。松开必须是单独的一句话，不能由模型在同一轮里自己松开。

## 10. 怎么分析对手的攻击 AI

Athena 不把对手的命令通道拆开，不保存对方载荷，不进入对方网络。能分析的是对手行为在**防守侧**留下的政策形状。

- 节奏过稳、触达面过宽：非人身份活得太久。动作是缩短令牌寿命。
- 工具调用突然变多：没有按租户封顶。动作是隔离。
- 要求新工具、新数据或新目标：这是范围扩张。动作停在提高挑战和人工闸门，不会把新工具加进清单。
- 话术带上已知泄漏字段的标记：入站仍把「知道名字」当成真人。动作是隔离该入站渠道。
- 同一序列反复出现：分段和蜜标不够。动作是提高蜜标密度。
- 委托方健康先下降：不能再把供应商当成自己的边界。动作是拉开已批准的断路器。
- 设定值往安全包络外走：物理命令走错了队列。动作是钳位。

注入守卫是另一条线。封闭名单里的分类器在冻结留出集上比较「把模型的目标改掉」和「正常的防守问题」。效果更好的留下。生成式模型，包括 GLM，不能混进这个分类器名单。新的文本分类仓库只变成治理提案，不自动下载。

GLM-5.3 若接通，系统提示要求它把己方遥测映射到十五个动作，并用两句人话回答。出现拒绝标记或攻击内容的回复会被丢弃。2026 年 7 月 Hugging Face 公开披露：他们在自己的机器上用 GLM-5.2 做取证，因为托管大模型拒读攻击日志。Athena 不把攻击命令当指令执行，也不宣称替他们上过值班。

## 11. 它不会做的事

- 不写利用步骤、载荷、扫描命令、钓鱼模板。
- 不付赎金，不联系攻击者，不给客户发消息。
- 不对外扫描，不进入供应商网络。
- 不微调基座模型来「学攻击」。
- 不因为模型建议就增加工具或数据源。
- 不把杀开关或物理联锁交给模型。
- 不在未点选时读取画面、摄像头、剪贴板或键盘。
- 不把演示租户、厂商营销数字或空的财务栏写成已发生的商业事实。

## 12. 若要把它讲成可上市的产品，还缺什么

架构上已经能讲清楚的是：谁有权行动、什么分数算赢、失败如何回滚、模型不能改哪些规则。上市还需要真实的法人、审计过的财务、客户合同和监管路径。仓库里没有这些，文档也不假装有。下一步如果要继续，是在同一宪法下把 Bot 用稳，而不是先写一份假想的招股书。
